- **الوثائق:** القسم 12 «التنفيذات» في `docs/pipeline-spec.md` و`docs/en/pipeline-spec.md`، و«Run» = «تنفيذ» في `Plan/Glossary.md`، و[ADR-0076](../ADR/0076-pipeline-runs-definitions-and-forks.md).

**لسه:**

## 2. M4.8: إصلاحات المراجعة الأمنية (`feat/pipelines-module`)

**اللي اتعمل:**
- **High (run مسموم):** `pipelinespec` بيرفض اسم تركيبة matrix أطول من 512 حرف (`MATRIX_NAME_TOO_LONG`، ومعاه الترجمة في `dhow lint`)، وكل loop في الـ worker والـ reconciler بيعزل العنصر: خطأ بيانات أو constraint بيعمل الـ run ده `failed` بـ `RUN_EXPANSION_FAILED`، والباقي بيكمّل. اختبار: run مسموم ورا run سليم في مؤسسة تانية، والسليم بيبدأ.
- **Medium (التثبيت بيقفل الـ worker):** ميزانية 30 ثانية للـ run، و4 بالتوازي، وكل صورة مرة واحدة، والـ reconciler على goroutine لوحده، وحد 60 run لكل مستخدم و240 لكل مشروع في 10 دقايق على `POST .../runs`. اختبارات: 8 صور بـ 300 ms بتخلص في أقل من 1.5 ثانية، وregistry معلّق بيفشّل الـ run بعد الميزانية، والـ reconciler بيصلّح run والـ starter واقف على run تاني، والطلب الـ 61 بياخد 429.
- **Medium (الجوع):** المرشّح من الطابور هو أول run في كل مجموعة مافيهاش run شغّال، والـ run اللي اتقيّم ومااتحرّكش بيروح آخر الطابور. اختباران: 101 run مستني في مجموعة مايمنعوش مجموعة تانية، و101 run طابور مؤسستهم مليان مايمنعوش run في مؤسسة تانية.
- **Low:** عنوان توكن الـ registry `https` على host الـ registry أو `auth.docker.io` أو `ghcr.io` وعلى منفذ معروف ومن غير النطاقات الخاصة، والـ outputs بتتقص تحت 60 KiB بـ `OUTPUTS_TRUNCATED`.
- **الـ sha اليدوي:** لازم وصل بـ webhook موثوق لنفس الـ ref (`SHA_NOT_ON_REF`)، ومن غيره آخر sha (`REF_HEAD_UNKNOWN`).
- **الـ forks والتكرار:** `Trigger.Origin` بثلاث قيم والافتراضي fork، ومفتاح التكرار فيه نوع الحدث و`IsFork`، والـ ref لازم يناسب الحدث.
- **`cancel_in_progress`** على نفس الـ ref بس، والـ refs التانية بتستنى.
- **JSON المخزّن** بيتفك بـ error ملفوف، والـ run بيفشل `RUN_STATE_INVALID`.
- الوثائق بالنسختين وADR-0076 وStatus.

**لسه:** تنفيذ `CheckoutSeam` بعد M4.7 (ومعاه التأكد إن الـ sha في تاريخ الـ ref)، والـ PR.

## 4. M4.7: الـ runner: أكتر من حاوية، والـ checkout، والإضافات (`feat/runner-checkout`)

**اللي اتعمل:**
- **`internal/gitsource` (ملزم من مراجعة M4.4):** `cmd.Env` صريح، و`--literal-pathspecs`، و`core.fsmonitor=false`، و`core.sshCommand` بمسار ثابت (الفاضي بيكسر git)، وhelper الـ ssh بـ `-F /dev/null` وسطر الـ host المتثبّت بس. واختبارات بـ git حقيقي و`GIT_SSH_COMMAND` و`GIT_DIR` متزرعين. والتحقق من الـ host اتنقل لـ `internal/hostname`.

- **السيرفر:** `"Runners"."Features"` (migration `00045`) من التسجيل والدخول الموقّع (`dhow/runner-auth/v2`)، والـ lease بالـ features، و`Enqueue` بيضيف الـ features اللي الـ spec محتاجها.

### بعد المراجعة الأمنية لـ M4.7
مفيش critical ولا high. اللي اتصلّح، وكل واحد معاه اختبار بيفشل من غير الإصلاح:
- **MEDIUM:** الإضافة بتاخد بس الـ `DHOW_INPUT_*` و`DHOW_OUTPUT` والـ proxy و`env` خطوتها والأسرار المحصورة في رقم خطوتها (السر في `with:` بقى SecretRef `DHOW_INPUT_<NAME>` محصور في الخطوة، و`jobspec` بيتحقق). ومابتاخدش `env` الـ job ولا أسرار الـ job كله ولا `DHOW_FENCING_TOKEN`.
- **LOW:** لو processes فضلت بعد هدم حاوية، الـ attempt بيفشل `SANDBOX_FAILED` قبل الحاوية اللي بعدها، والـ slot مابيرجعش.
- **LOW:** الـ jobs اليدوية بقت تاخد الـ features من الـ spec (وjob إضافات بس بقى يتخزّن، لأن عمود `"Image"` كان رافض الصورة الفاضية).
- **LOW:** الأخطاء اللي كانت بتتجاهل حوالين ملف الـ host key وملف الـ outputs.
- **LOW:** الـ outputs بتتخفى كمجموعة، فسر متقسّم على أكتر من مفتاح بيشيل المفاتيح دي.
- **S1:** الـ workspace بيتراجع قبل كل حاوية (tmpfs و`nosuid,nodev` وفي حدود الحجم)، وإلا `SANDBOX_FAILED`.
- **S2:** كل حزم apk في صورة `dhow-git` متثبّتة بنسخها، و`make git-image-pins` بيطبع النسخ للتحديث.

الـ isolation suite اتشغّل تاني على Podman 5.6.2 rootless (cgroup v1): 22 من 24 عدّوا، والاتنين الفاشلين حدود الذاكرة والـ CPU زي قبل كده.
